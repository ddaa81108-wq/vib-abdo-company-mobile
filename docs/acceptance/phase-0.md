# المرحلة 0 — توثيق العقد وتأكيد قرارات الخادم

**النطاق:** كل بند معلَّم 🔶 مع مالك الخادم: `fullAccess`، أكواد الإجراءات الإدارية، `cashStatus`، `GET /api/home`، مصادقة الجوال، `MONEY_UNIT_SCALE`، صيغة السعر، عملة فودافون، حالات يوم المشتريات، حالات التقارير.

**المخرجات المطلوبة:** وثيقة عقد API بإصدار رقمي، وجدول «حقل ← مؤكد أو مرفوض أو بديل»، ومصفوفة أدوار معتمدة، ورابط staging وحسابات اختبار خارج المستودع.

**حالة التنفيذ في هذه الجولة:** `Not run`. المرحلة شرط مسبق ولم تُطلب تجربة تشغيلها. الملاحظة الوحيدة من وجود الملفات: لا وثيقة عقد معتمدة ولا حسابات staging داخل المستودع. هذا لا يغيّر الحالة إلى Fail.

طريقة التعبئة عند التنفيذ: فحص وثيقة العقد مع مالك الخادم، لا اختبار واجهة.

---

#### P0-01 — قرار مكتوب لكل بند مقترح

- **النوع:** functional
- **الأولوية:** عالية
- **الحالة:** Not run
- **الشروط المسبقة:** قائمة البنود المعلَّمة في `api_endpoints.dart` و`permission_codes.dart` وملفات `*_models.dart` (ابحث عن 🔶 أو `PROPOSED` أو `pending server`).
- **الخطوات:**
  1. استخرج كل حقل أو مسار يصفه الكود بأنه مقترح.
  2. قابل كل بند بصف في وثيقة العقد: مؤكد، أو مرفوض، أو بديل مع الاسم الجديد.
  3. تأكد أن الوثيقة تحمل رقم إصدار.
- **النتيجة المتوقعة:** لا بند 🔶 بلا قرار مكتوب، والإصدار ظاهر في رأس الوثيقة.

#### P0-02 — اعتماد قائمة الأدوار ومصفوفتها

- **النوع:** permissions
- **الأولوية:** عالية
- **الحالة:** Not run
- **الشروط المسبقة:** القسم 4 من التحليل، و`docs/acceptance/permissions-matrix.md` كمسودة تقنية لا كاعتماد إداري.
- **الخطوات:**
  1. اعرض على الإدارة الأدوار الفعلية (مدير كامل، إداري محدود إن اعتُمد، موظف استلام، وأي دور آخر).
  2. حدّد لكل دور أكواد `permissions` وقيم `sectionAccess`.
  3. وقّع المصفوفة أو اطلب تعديل القسم 4.
- **النتيجة المتوقعة:** مصفوفة موقَّعة. الأدوار غير المعتمدة لا تُستخدم في حسابات الاختبار.

#### P0-03 — تسليم staging وحسابات الاختبار

- **النوع:** networks
- **الأولوية:** عالية
- **الحالة:** Not run
- **الشروط المسبقة:** بيئة staging منعزلة عن الإنتاج. لا تُوضع الأسرار في المستودع.
- **الخطوات:**
  1. استلم عنوان HTTPS ونطاقه المسموح.
  2. استلم حسابًا لكل دور، منها حساب `mustChangePassword = true` إن كان العلم مؤكدًا.
  3. خزّن الأسرار خارج المستودع واتفق على أمر التشغيل `--dart-define=USE_FAKE_API=false --dart-define=API_BASE=...`.
- **النتيجة المتوقعة:** يستطيع مختبر الدخول من جهاز تجريبي بلا تعديل أسرار مُلتزَم بها في Git.

#### P0-04 — حسم المصادقة ووحدة المال والصيغ

- **النوع:** functional
- **الأولوية:** عالية
- **الحالة:** Not run
- **الشروط المسبقة:** بنود التحليل 5 و6 و7 و10 و11 (Cookie/CSRF مقابل Bearer، `MONEY_UNIT_SCALE`، صيغة السعر، عملة فودافون، حالات اليوم والتقرير).
- **الخطوات:**
  1. سجّل القرار لكل بند في جدول الحقل.
  2. إن رُفض علم أو كود مقترح، اكتب البديل الذي يجب أن يتبعه التطبيق لاحقًا.
- **النتيجة المتوقعة:** جدول مكتمل يُستخدم كمدخل لتعديل المراحل 1–5، بلا تخمين داخل جولة القبول.
